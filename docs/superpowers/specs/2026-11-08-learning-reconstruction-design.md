# 학습 경험 재구성 기획안

기준일: 2026-11-08. 기준 구현: `72b36cf`. 사용자는 브리핑의 방향을 승인하고 필요한 본인 작업만 요청하도록 위임했다. 아래의 시각·구현 선택은 그 범위에서 내린 개발 판단이다.

## 목적과 근거

실물 3×3 큐브를 가진 초보자가 혼자 자신의 시작 지점을 찾고, 사례와 잡는 방향을 고른 뒤 동작을 따라 하고 실물을 확인하도록 돕는다. 기존 구현에는 회전 모델·9개 수업·양언어 안내·49개 통과 테스트가 있다. 실제 초보자의 성공률과 소요 시간은 측정되지 않았다. 이 작업으로 학습 성과가 개선됐다고 단정하지 않는다.

## 대안과 선택

| 대안 | 장점 | 비용·한계 | 판단 |
| --- | --- | --- | --- |
| 기존 화면의 배치만 조정 | 변경량이 작다 | 상태 탐색과 막힘 해결의 구조를 충분히 검토하기 어렵다 | 비교 기준으로 보존 |
| 학습 흐름을 재구성하고 모델·수업 재사용 | 정확성 자산을 유지하면서 안내 동선을 바꿀 수 있다 | 전체 경로의 회귀 검사 필요 | 이번 구현 |
| 프레임워크·회전 엔진까지 새로 작성 | 기술 선택의 자유 | 현재 근거로는 비용과 오류 위험을 정당화하기 어렵다 | 필요가 측정될 때 검토 |

## 범위와 우선순위

### 이번 묶음

1. 홈에 순서가 있는 시작 지점 찾기와 직접 확인한 수업의 진행 표시를 제공한다.
2. 모든 수업을 사례 고르기 → 잡는 방향 → 시연 따라 하기 → 실물 확인으로 재구성한다.
3. 화면·실물 차이, 진행 위치 분실, 이전 층 변화에 대한 복구 안내를 제공한다.
4. 한국어·영어, 작은 화면, 키보드, 움직임 감소, 저장소 차단, JavaScript 미사용을 유지한다.
5. 새 의존성 없이 실제 Astro 화면으로 검증한다. 큐브 상태·도해는 기존 데이터에서 만든다.
6. 사용자 평가 절차와 반복 개발 절차를 문서로 남긴다.

### 후속 판단 항목

카메라 인식, AI 튜터, 계정·동기화, 음성 안내, 보상·게임화는 별도 사용자 근거와 비용 검토가 필요하다. Figma·Penpot은 시각적 협업이 필요해질 때 연결한다. 이번 수업 화면에는 비트맵 장식의 필요가 확인되지 않아 생성 이미지를 넣지 않는다.

## 학습 흐름

- **홈:** 흰 십자부터 시작 / 이전 기록 이어 보기 / 지금 맞춘 상태로 시작 지점 찾기 / 전체 수업 순서.
- **고르기:** 시작 전 조건과 사례 선택, 해당 사례의 조건을 한곳에서 읽는다.
- **잡기:** 선택한 사례의 잡는 방향을 시연 전에 확인한다.
- **따라 하기:** 한 동작·묶음 재생·확인 지점·공식·관찰 조작을 기존 상태 모델과 연결한다.
- **확인:** 독자가 자신의 큐브에서 종료 조건을 확인하고 다음 단계로 이동한다.
- **막힘:** 시연을 멈추고 조건·방향·진행 순서를 다시 확인한다. 화면 되돌리기는 실물을 되돌리지 않는다.

시작 지점은 사용자의 자기 확인에 따른 안내다. 인식·진단 기능으로 표현하지 않는다. 본 수업은 흰 십자부터 7단계이며 준비와 꽃 모양은 보조 설명이다. 관찰 방향 변경은 큐브 상태를 바꾸지 않는다. 마지막 꼭짓점 단계의 일시적인 아래층 변화는 오류로 단정하지 않는다.

## 디자인 방향과 비교안

독자의 익숙한 체계로 실습 노트, 길찾기 안내, 조립 설명서, 레시피, 조작 패널, 단계별 작업표, 수학 도해를 비교했다. 단계별 작업표를 바탕으로, 각 행동의 위치와 순서를 같은 언어로 반복하는 실습 화면을 선택한다. 디자인 시드 `f995b3f4`, assigned index 6. 사용자가 위임한 실제 브라우저 중심 구현으로 진행한다.

- 홈: 왼쪽의 짧은 시작 안내와 오른쪽 큐브·층별 목표를 하나의 작업 시작 면으로 구성한다.
- 수업: 큰 단계 번호와 목표, 사례·잡는 방향의 준비 영역, 시연과 방법의 실습 영역, 실물 확인과 복구 영역을 연결한다.
- 밝은 중립 바탕, 짙은 잉크, 명확한 파란 행동색을 사용한다. 큐브 여섯 색은 상태 표현으로 유지한다.
- 버튼과 조작은 실제 행동명을 사용하고, 보조 기능은 필요한 곳에서 펼친다.
- 모바일은 준비 → 시연 → 확인 순서로 읽으며 가로 스크롤을 요구하지 않는다.

대안 A는 긴 설명을 먼저 읽는 문서형, 대안 B는 사례와 시연이 이어지는 실습형이다. 이번에는 B를 구현한다. 기존 화면 캡처는 `artifacts/baseline/`에 있으며 새 화면과 같은 폭에서 비교한다. 이는 실제 사용자 선호가 확인된 선택이 아니라 검증할 설계 가설이다.

## 재사용 자산

- `src/lib/cube.ts`: 회전·상태·완성 판정.
- `src/content/lessons.ts`, `guidance.ts`: 수업·사례·시작 및 종료 조건.
- `src/scripts/lesson.ts`, `cube-view.ts`, `formula-guide.ts`: 시연과 조작.
- `src/lib/progress.ts`: 기존 브라우저 기록 형식. 참고 수업 방문과 본 수업 완료는 구분한다.
- 기존 회전·해법·접근성 검사. 테스트를 약화해 새 화면에 맞추지 않는다.

## 수용 기준

1. 시작 지점 안내의 7개 링크는 본 수업 순서와 일치하고 각 시작 조건을 양언어로 제공한다.
2. 진행 표시의 분모는 본 수업 7개다. 보조 수업 완료는 집계하지 않고 저장 실패 시 읽기를 유지한다.
3. 사례 선택과 잡는 방향이 시연보다 먼저 등장하고 사례 변경 시 조건·방향·공식이 함께 갱신된다.
4. 복구 도움말을 열면 재생이 멈추며, 화면 되돌리기와 실물 되돌리기를 구분한다.
5. 시연 종료가 수업 완료 기록을 자동으로 만들지 않는다. 기존 직접 확인 버튼이 완료의 기준이다.
6. 마지막 꼭짓점 수업은 아래층을 따로 고치지 않는 안내와 최종 여섯 면 확인을 유지한다.
7. 320·360·390·768·1280px, 두 언어, 두 테마, 200% 글자 확대에서 기능과 내용을 사용할 수 있다.
8. JavaScript 미사용에서도 시작 링크·수업 설명·복구 안내를 읽을 수 있다.
9. `npm test`, `npm run check`, `npm run build`, `npm run test:site`, `npm run test:browser`를 통과한다.

## 실제 사용자 검증과 측정

초보자에게 실제 큐브와 휴대전화를 주고 시작 지점 찾기, 흰 십자, 2층 삽입, 마지막 꼭짓점의 과제를 관찰한다. 연구자가 조작을 대신하지 않고 도움 요청·방향 착오·사례 오선택·확인 누락을 기록한다. 화면 재생 종료와 실물 성공은 따로 기록한다. 완료율은 시도한 참가자 수와 성공한 참가자 수를 함께 보고하고 중도 이탈을 누락하지 않는다. 소수의 탐색 관찰로 모집단 성공률을 추정하지 않는다.

사용자가 꼭 해야 할 일은 실제 초보자 모집과 관찰 결과 제공이다. 테스트 도구로 이 부분을 대체했다고 주장하지 않는다. 구체적인 요청은 프로토타입과 관찰지가 준비된 뒤 전달한다.

## AI 작업 운영

과제마다 목표·입력·수정 범위·금지 사항·수용 기준·검증 명령을 고정한다. 최대 3회의 자동 수정 단위에서 같은 실패가 반복되면 원인을 재검토한다. 기획은 사용자 관찰, 디자인은 실제 화면, 구현은 실행 결과를 다음 반복의 입력으로 사용한다. 기존 스킬로 충분한 절차는 재사용하고 중복 스킬 설치를 피한다. 공개 스킬은 도구명·경로·운영체제·라이선스·의존성을 확인한 뒤 도입한다.
